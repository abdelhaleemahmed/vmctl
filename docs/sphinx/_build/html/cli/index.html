CLI Reference

Complete reference for all vmctl commands, generated from the source code.

vmctl

vmctl — Virtual Machine Management Tool.

Manage VirtualBox VMs with config-as-code support. Export any VM to YAML or JSON, recreate it anywhere, and spin up entire clusters from a single batch file.

Quick start:
vmctl list
vmctl export my-vm -o my-vm.yaml
vmctl import my-vm.yaml –new-name test-vm
vmctl import my-vm.yaml –new-name test-vm –execute
vmctl batch create cluster.yaml –execute
vmctl [OPTIONS] COMMAND [ARGS]...

Options

-V, --version

Show the version and exit.

batch

Create multiple VMs from a batch definition file.

vmctl batch [OPTIONS] COMMAND [ARGS]...

create

Create VMs from a batch definition file.

The batch file defines a base VM and a list of named instances with optional per-instance overrides for CPU, memory, and disks.

Without –execute the command summarises what would be created.

Examples:
vmctl batch create cluster.yaml
vmctl batch create cluster.yaml –execute
vmctl batch create [OPTIONS] BATCH_FILE

Options

--execute

Actually create the VMs (dry-run by default).

Arguments

BATCH_FILE

Required argument

template

Generate a starter batch template file.

The generated file contains a working example with three VM instances that can be customised and used with ‘vmctl batch create’.

Example:
vmctl batch template -o my-cluster.yaml
vmctl batch template [OPTIONS]

Options

-o, --output <output>

Output file path.

Default:

PosixPath('batch-template.yaml')

--format <fmt>

Output format.

Default:

'yaml'

Options:

yaml | json

completion

Print shell completion script to stdout.

Source the output to enable tab completion for vmctl commands and VM names in your current shell session.

Setup:
# Bash (add to ~/.bashrc for permanent activation):
eval “$(vmctl completion bash)”

# Zsh (add to ~/.zshrc): eval “$(vmctl completion zsh)”

# Fish (add to ~/.config/fish/config.fish): vmctl completion fish | source

vmctl completion [OPTIONS] {bash|zsh|fish}

Arguments

SHELL

Required argument

create

Clone a VM configuration from an existing VirtualBox VM.

Reads the source VM’s configuration live from VirtualBox, applies any overrides, and creates a new blank VM with the same hardware profile. Disk contents are NOT copied.

Examples:
vmctl create ubuntu-server –new-name ubuntu-clone
vmctl create ubuntu-server –new-name ubuntu-clone –execute
vmctl create ubuntu-server –new-name small-clone –cpus 2 –memory 2048 –execute
vmctl create [OPTIONS] SOURCE_VM

Options

--new-name <new_name>

Required Name for the new VM.

--memory <memory>

Override memory in MB.

--cpus <cpus>

Override CPU count.

--execute

Actually create the VM (dry-run by default).

Arguments

SOURCE_VM

Required argument

delete

Unregister a VM and delete all associated disk files.

This action is irreversible. Without –force, you will be asked to confirm before anything is deleted.

Examples:
vmctl delete old-vm
vmctl delete old-vm –force
vmctl delete [OPTIONS] VM_NAME

Options

-f, --force

Skip confirmation prompt.

Arguments

VM_NAME

Required argument

edit

Modify CPU, memory, or name of an existing VM.

The VM should be stopped before changing CPU or memory settings.

Examples:
vmctl edit my-vm –cpus 8
vmctl edit my-vm –memory 16384
vmctl edit my-vm –new-name renamed-vm
vmctl edit [OPTIONS] VM_NAME

Options

--new-name <new_name>

Rename the VM.

--memory <memory>

Set memory in MB.

--cpus <cpus>

Set CPU count.

Arguments

VM_NAME

Required argument

export

Save a VM’s configuration to a YAML or JSON file.

The VM does not need to be stopped before exporting.

Examples:
vmctl export ubuntu-server -o ubuntu-server.yaml
vmctl export ubuntu-server -o ubuntu-server.json –format json
vmctl export [OPTIONS] VM_NAME

Options

-o, --output <output>

Required Output file path (.yaml or .json).

--format <fmt>

Output format (inferred from extension if not specified).

Default:

'yaml'

Options:

yaml | json

Arguments

VM_NAME

Required argument

import

Create a VM from a YAML or JSON configuration file.

Without –execute the command prints the VBoxManage commands that would be run but does not touch VirtualBox (dry-run mode).

Note: import creates a new VM with a blank disk. It does not copy disk contents. Use Bareos, rsync, or a similar tool to restore data.

Examples:
vmctl import ubuntu-server.yaml –new-name test-server
vmctl import ubuntu-server.yaml –new-name test-server –execute
vmctl import [OPTIONS] CONFIG_FILE

Options

--new-name <new_name>

Override the VM name from the file.

--execute

Actually create the VM (dry-run by default).

Arguments

CONFIG_FILE

Required argument

list

List all VMs registered in VirtualBox.

TABLE format (default) shows each VM name alongside its current status. SIMPLE format prints only the names, one per line — useful for scripting.

Examples:
vmctl list
vmctl list –format simple
vmctl list [OPTIONS]

Options

--format <fmt>

Output format.

Default:

'table'

Options:

table | simple

read

Print a VM’s configuration to stdout.

Reads the live configuration directly from VirtualBox and outputs it as YAML (default) or JSON.

Examples:
vmctl read ubuntu-server
vmctl read ubuntu-server –format json
vmctl read [OPTIONS] VM_NAME

Options

--format <fmt>

Output format.

Default:

'yaml'

Options:

yaml | json

Arguments

VM_NAME

Required argument

start

Start a VM in headless mode.

The VM has no GUI window. Use VirtualBox GUI or SSH to interact with the guest once it has booted.

Example:
vmctl start ubuntu-server
vmctl start [OPTIONS] VM_NAME

Arguments

VM_NAME

Required argument

status

Show the current state of a VM.

Possible states: running, stopped, paused, saved, aborted, starting, stopping, unknown.

Example:
vmctl status ubuntu-server
vmctl status [OPTIONS] VM_NAME

Arguments

VM_NAME

Required argument

stop

Stop a running VM.

Without –force, sends an ACPI shutdown signal so the guest OS can shut down cleanly. Use –force only when the guest is unresponsive.

Examples:
vmctl stop ubuntu-server
vmctl stop ubuntu-server –force
vmctl stop [OPTIONS] VM_NAME

Options

-f, --force

Force power-off (equivalent to pulling the power cord).

Arguments

VM_NAME

Required argument

validate

Validate a YAML or JSON VM configuration file.

Runs four validation phases: schema, provider limits, logical constraints, and warnings. Exits with code 1 on error.

Example:
vmctl validate my-config.yaml
vmctl validate [OPTIONS] CONFIG_FILE

Arguments

CONFIG_FILE

Required argument
