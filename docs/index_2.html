How It Works

Three steps from a running VM to a reproducible, version-controlled machine definition

1

Capture

Export any existing VirtualBox VM to a plain YAML file. CPU, RAM, disks, network adapters, firmware — everything is captured exactly.

vmctl export my-vm -o my-vm.yaml
→
2

Version Control

The YAML file is human-readable and diff-friendly. Put it in Git alongside your code — treat your infrastructure like software.

git add my-vm.yaml && git commit
→
3

Recreate

Import the file anywhere to create an identical VM. Preview with dry-run first, then execute. Batch-create entire clusters the same way.

vmctl import my-vm.yaml --execute

Human-Readable Config

One command produces a clean YAML file you can read, edit, and diff in any text editor

ubuntu-server.yaml YAML
name: ubuntu-server ostype: Ubuntu_64 description: Production web server   cpu: count: 4 nested_virt: false   memory: mb: 8192 vram_mb: 16   firmware: type: EFI64 secure_boot: false   disks: - name: system size_mb: 51200 type: HDD format: VDI variant: THIN controller: SATA bootable: true   networks: - network_type: BRIDGED adapter_name: enp3s0 - network_type: HOSTONLY   boot: order: [disk, dvd, none, none] acpi: true ioapic: true
Export existing VM SHELL
$ vmctl export ubuntu-server \ -o ubuntu-server.yaml   ✓ Saved ubuntu-server → ubuntu-server.yaml
Validate before import SHELL
$ vmctl validate ubuntu-server.yaml   Configuration is valid! VM Name: ubuntu-server CPU: 4 cores Memory: 8192 MB Disks: 1
Recreate anywhere SHELL
$ vmctl import ubuntu-server.yaml \ --new-name dev-clone --execute   ✓ VM 'dev-clone' created successfully

Everything You Need

A complete toolkit for managing VirtualBox VMs from the command line

📄

Config-as-Code

Every VM is a plain YAML or JSON file. Export any running VM, put it in Git, and recreate it anywhere. CPU, RAM, disks, network adapters, firmware — everything is captured.

👁️

Dry-Run by Default

Create, import, and batch commands show the exact VBoxManage commands that would run before touching anything. Pass --execute when ready.

🗂️

Batch VM Creation

Define a base VM once, then spin up any number of instances with selective overrides for CPU, RAM, disk size, and network. One command creates the whole cluster.

💾

Flexible Disk Support

VDI, VMDK, VHD, and RAW formats. Thin (dynamic) and thick (fixed) provisioning. IDE, SATA, SCSI, and SAS controllers. CD-ROM drives are correctly identified as optical, not hard disks.

🌐

Full Network Control

NAT, Bridged, Host-only, Internal, and NatNetwork adapters. Up to 8 per VM. Set adapter model, MAC address, and promiscuous mode from config.

✅

4-Phase Validation

Schema, provider limits, logical constraints, and warnings — all checked before any VM is created. Catches typos, constraint violations, and duplicate names up front.

🔧

Full Lifecycle Management

List, start, stop (graceful or forced), status, edit, and delete VMs all from one tool. No need to open the VirtualBox GUI for routine operations.

⚙️

Firmware & Boot Control

BIOS, EFI, EFI64, and EFI32 firmware. Secure Boot and TPM support. Configurable boot device order across disk, DVD, network, and floppy.

🔌

Extensible Provider System

VirtualBox is the first provider. The abstract provider interface is designed to support libvirt/KVM and QEMU — contributions welcome.

Command Reference

All commands support --help for detailed usage

Command Description
⚡ Lifecycle
vmctl list [--format table|simple] List all VMs with their current status
vmctl status <vm> Show current state: running, stopped, paused, saved, aborted
vmctl start <vm> Start VM in headless mode
vmctl stop <vm> [-f] Graceful ACPI shutdown; force power-off with -f
vmctl delete <vm> [-f] Unregister VM and delete all associated disk files
📄 Configuration
vmctl read <vm> [--format yaml|json] Print a VM's full configuration to stdout
vmctl export <vm> -o <file> Save VM configuration to a YAML or JSON file
vmctl import <file> [--new-name <n>] [--execute] Create a VM from a config file (dry-run by default)
vmctl create <vm> --new-name <n> [--execute] Clone configuration from an existing VirtualBox VM
vmctl edit <vm> [--memory MB] [--cpus N] Modify CPU, RAM, or name of an existing VM
vmctl validate <file> Validate a config file and report errors or warnings
🗂️ Batch
vmctl batch create <file> [--execute] Create multiple VMs from a batch definition file
vmctl batch template [-o <file>] Generate a starter batch YAML template
vmctl --version Show installed version

Real-World Scenarios

Common workflows that vmctl makes straightforward

🔥

Disaster Recovery Testing

Export a production VM config, create a blank clone with identical hardware, boot a recovery ISO, restore from backup, verify it boots. Repeat on demand.

# Capture production config vmctl export prod-server -o prod.yaml # Spin up blank recovery target vmctl import prod.yaml \ --new-name bmr-test --execute # Boot from rescue ISO, restore, verify vmctl delete bmr-test --force
👩‍💻

Team Dev Environments

Store the whole lab as a batch YAML in Git. Every developer clones the repo and runs one command to get identical machines — no more "works on my machine."

# Clone the team's lab definition git clone https://github.com/team/lab # Spin up all VMs at once vmctl batch create lab/cluster.yaml \ --execute # web-01, web-02, db-01 created ✓
🏗️

Infrastructure as Code

Every VM change gets committed. Diffs are readable. Roll back by checking out an earlier config and re-importing. Your VM inventory lives next to your application code.

# Update and track the change vmctl export web-server \ -o infra/web-server.yaml git diff infra/web-server.yaml git commit -m "Increase RAM to 8 GB" # Recreate from any past commit

Installation

Requires Python 3.8+ and VirtualBox with VBoxManage in PATH

# Install from PyPI
pip install vmctl

# Verify installation
vmctl --version
vmctl 1.1.8

# Confirm VirtualBox is accessible
VBoxManage --version
# Clone and install in editable mode
git clone https://github.com/ahmedhal/vmctl.git
cd vmctl
pip install -e .

# Verify
vmctl --version
# List your VMs
vmctl list

# Export a VM to YAML
vmctl export my-vm -o my-vm.yaml

# Preview what would be created (dry-run)
vmctl import my-vm.yaml --new-name test-vm

# Actually create it
vmctl import my-vm.yaml --new-name test-vm --execute

# Start and check status
vmctl start test-vm
vmctl status test-vm
