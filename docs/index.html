Everything You Need

A complete toolkit for managing VirtualBox VMs from the command line

📄

Config-as-Code

Every VM is a plain YAML or JSON file. Export any running VM, put it in Git, and recreate it anywhere. CPU, RAM, disks, network adapters, firmware — everything is captured.

👁️

Dry-Run by Default

Create, import, and batch commands show the exact VBoxManage commands that would run before touching anything. Pass --execute when ready.

🗂️

Batch VM Creation

Define a base VM once, then spin up any number of instances with selective overrides for CPU, RAM, disk size, and network. One command creates the whole cluster.

💾

Flexible Disk Support

VDI, VMDK, VHD, and RAW formats. Thin (dynamic) and thick (fixed) provisioning. IDE, SATA, SCSI, and SAS controllers. CD-ROM drives are correctly identified as optical, not hard disks.

🌐

Full Network Control

NAT, Bridged, Host-only, Internal, and NatNetwork adapters. Up to 8 per VM. Set adapter model, MAC address, and promiscuous mode from config.

✅

4-Phase Validation

Schema, provider limits, logical constraints, and warnings — all checked before any VM is created. Catches typos, constraint violations, and duplicate names up front.

🔧

Full Lifecycle Management

List, start, stop (graceful or forced), status, edit, and delete VMs all from one tool. No need to open the VirtualBox GUI for routine operations.

⚙️

Firmware & Boot Control

BIOS, EFI, EFI64, and EFI32 firmware. Secure Boot and TPM support. Configurable boot device order across disk, DVD, network, and floppy.

🔌

Extensible Provider System

VirtualBox is the first provider. The abstract provider interface is designed to support libvirt/KVM and QEMU — contributions welcome.

Command Reference

All commands support --help for detailed usage

Command Description
vmctl list [--format table|simple] List all VMs with their current status
vmctl status <vm> Show current state: running, stopped, paused, saved, aborted
vmctl start <vm> Start VM in headless mode
vmctl stop <vm> [-f] Graceful ACPI shutdown, or force power-off with -f
vmctl read <vm> [--format yaml|json] Print a VM's full configuration to stdout
vmctl export <vm> -o <file> Save VM configuration to a YAML or JSON file
vmctl import <file> [--new-name <n>] [--execute] Create a VM from a config file (dry-run by default)
vmctl create <vm> --new-name <n> [--execute] Clone configuration from an existing VirtualBox VM
vmctl edit <vm> [--memory MB] [--cpus N] Modify CPU, RAM, or name of an existing VM
vmctl delete <vm> [-f] Unregister VM and delete all associated disk files
vmctl validate <file> Validate a config file and report errors or warnings
vmctl batch create <file> [--execute] Create multiple VMs from a batch definition file
vmctl batch template [-o <file>] Generate a starter batch YAML template
vmctl --version Show installed version

Installation

Requires Python 3.8+ and VirtualBox with VBoxManage in PATH

# Install from PyPI
pip install vmctl

# Verify installation
vmctl --version
vmctl 1.1.8

# Check VirtualBox is accessible
VBoxManage --version
# Clone and install in editable mode
git clone https://github.com/abdelhaleemahmed/vmctl.git
cd vmctl
pip install -e .

# Verify
vmctl --version
# List your VMs
vmctl list

# Export a VM to YAML
vmctl export my-vm -o my-vm.yaml

# Preview what would be created (dry-run)
vmctl import my-vm.yaml --new-name test-vm

# Actually create it
vmctl import my-vm.yaml --new-name test-vm --execute

# Start and check status
vmctl start test-vm
vmctl status test-vm
